# config/hypr

KubaOS's Hyprland 0.56+ Lua config, plus hypridle and hyprlock (those two still use
hyprlang `.conf`). These are KubaOS's defaults, linked read-only into
`~/.config/hypr` by home-manager; editing them here takes a `home-manager switch`.
Your own settings go in `~/.config/kubaos/desktop/hypr/` (`hyprland.lua`, `hypridle.conf`,
`hyprlock.conf`), which load last.

## Files

| File | What |
|---|---|
| `hyprland.lua` | Entry point, `require`s the modules below in order |
| `fallback.lua` | Binds that never depend on Quickshell or Nix (loaded first) |
| `env.lua` | Environment: PATH, Wayland vars for Qt/GTK/Electron/Chrome, cursor size |
| `monitors.lua` | Every screen at its preferred mode, placed by Hyprland; the laptop panel off while the lid is closed on a dock, and its refresh rate and VRR as the power stop sets them (`dot.power_panel()`, over your own panel rule too, keeping its position and scale). Your own layout: below |
| `workspaces.lua` | Per-screen workspaces: each screen has its own 1-10 (a block of ten ids, the laptop's first), joins another on unplug and returns on replug, and the screens pinned to a group in `~/.config/kubaos/desktop/workspaces/groups.toml`. `workspace_blocks.lua` is its bookkeeping, tested by `test/lua/workspaces_test.lua` |
| `input.lua` | Keyboard layouts from `~/.config/kubaos/desktop/keyboard/keyboard.toml`, else `/etc/default/keyboard` (`us` without either), repeat rate, touchpad, gestures, the `kubaos:mac-accents` XKB option |
| `accents.lua` | The Mac-style accents' cheat sheet for the Shortcuts View, while they are on |
| `looks.lua` | Gaps, borders, rounding, blur, shadows, animations, dwindle, colors. Sizes and curves match the design tokens (`design/tokens.toml`); `rounding = 14` plus the 2 px border makes the window's outer edge concentric with the frame's 24 px corners (the surface radius) at `gaps_out = 8` |
| `focus.lua` | The active window's neon focus: its border the focus tube in `primary`, its shadow the glow in `primary`, and the strike they play as focus moves to another window, unless `focusStutter` is off (`docs/DESIGN.md`, "States"). It owns the active border and shadow colours and the `border` and `fadeShadow` animations, which it turns off during a strike: set those two from your layer with `dot.focus.fade({ leaf = "border", ... })`, not `hl.animation`, or the first strike puts looks.lua's back. Tested by `test/lua/focus_test.lua` |
| `tokens.lua` | Generated by `kubaos-tokens` from `design/tokens.toml` in the Nix build, so not in the repo (`just tokens` writes it into a checkout): the durations, curves, focus glow and strike Hyprland uses |
| `colors.lua` | Reads `~/.local/state/theme/hypr.lua`, falls back to built-in colors |
| `rules.lua` | Window rules (floating dialogs, PiP, Chrome, terminals) and layer rules, including Quickshell's (`qs-frame` blurred with `ignore_alpha`, no Hyprland animation on the shell's own layers) |
| `keybinds.lua` | Everything else, ported from Omarchy 4. `SUPER + F1` lists them all in the Command menu |
| `autostart.lua` | Session startup; the polkit agent toggle is at the top |
| `hypridle.conf` | hypridle's `general` block; the listeners (lock 5 min, screens off 10 min, suspend 30 min on battery only by default) come from the idle settings through `kubaos-idle` (`crates/kubaos-idle`) |
| `hyprlock.conf` | Fallback lock screen, themed, fingerprint enabled |
| `~/.config/kubaos/desktop/hypr/hyprland.lua` | Yours, not in the repo: loaded last (`docs/CONTRACTS.md`, "Defaults and the user layer") |

Scripts (in `scripts/`, linked to `~/.local/bin`): `dot-hypr-workspaces`
(event-socket listener, runs `dot-hypr-lid sync` on hotplug), `dot-hypr-lid`
(laptop panel off when the lid closes with an external connected),
`dot-hypr-on-ac` (used by hypridle), `dot-hypr-screenshot` (a region shot freezes the
screen with hyprpicker, then crops the selection from a grim capture taken first).

## Reload

- Hyprland reloads by itself when a config file changes. Manually:
  `hyprctl reload` or `SUPER + SHIFT + CTRL + R`.
- Errors show as a banner and in `hyprctl configerrors`. Check without
  applying: `Hyprland --verify-config`.
- Colors only: `hyprctl eval 'dot.reload_colors()'` (what `dot-theme` should
  call after writing `hypr.lua`; `hyprctl reload` also works).
- hypridle: `kubaos-idle apply` writes the listeners again and restarts it
  in the session (`dot-session start-idle`). hyprlock reads its config on
  every start.
- Poke at the live Lua state: `hyprctl repl`.

## Your screens

The defaults place every screen at its preferred mode. Set your own layout in
`~/.config/kubaos/desktop/hypr/hyprland.lua`, one line per screen:

1. Run `hyprctl monitors all`: each screen's `description:` (make, model,
   serial) and `availableModes`.
2. Add a line per screen, matched by description so it follows the screen
   to any port or dock:

   ```lua
   hl.monitor({ output = "desc:Dell Inc. DELL U2724D 1A2B3C4", mode = "2560x1440@120", position = "1920x0", scale = 1 })
   ```

   `position` is the top-left corner in logical pixels (after scale): a
   screen to the right of a 1920-wide one starts at `x = 1920`.
3. `hyprctl reload`.

A line of your own for `eDP-1` replaces the lid rule above it: copy the flag
check from `monitors.lua` around it, or the panel stays on with the lid
closed. Workspaces follow these positions: the leftmost external shows the
first external group, whatever screen it is (see Workspaces below), so place
your screens in the order they stand on the desk. Without lines of your own,
Hyprland places them in connector order. Or pin each screen to its group
(Workspace groups, below), and the layout doesn't decide.

## Workspaces

Each screen has workspaces 1-10 of its own: `SUPER + 1..0` go to the
focused screen's, `SUPER + arrows` focus another screen. Hyprland numbers
workspaces globally, so `workspaces.lua` gives each screen a block of ten ids
(the laptop panel 1-10, the next screen 11-20) and the bar labels them 1-10.

A block belongs to a position on the desk, not to a screen. The laptop panel
is one position; the externals are positions 1, 2 and on, counted left to
right by where Hyprland places them (top to bottom at the same x). Whatever
screen stands at position 1 shows position 1's workspaces, so with two
screens beside the laptop at work and two others at home, carrying the
laptop from one desk to the other brings the windows along: the left screen
at home shows what the left one at work did. Without pins (below) there is
nothing to pair; only the order counts, so place the screens in the order
they stand (above).

A position's workspaces are its group. When fewer screens are plugged in,
the group of a position no screen holds waits on the primary screen (the
laptop panel; with the lid closed, the external Hyprland numbered first)
under its own numbers, if it had any windows; an empty group vanishes. The
next screen to take that position takes the group back. A position never seen
before gets a new group. Unplugging the leftmost of three screens shifts the
others one position left, and each group goes to the screen now at its
position. The bar shows each group on its own, a thin rule between them,
e.g. `1 2 3 | 1 2`, in block order: the screen's own first, then the waiting
groups, each on a tint so it reads as borrowed. Block order is id order, the
order Hyprland's swipe walks a screen's workspaces in, so the one screen that
sees a waiting group before its own is an external holding the laptop's
group (1-10) while the lid is closed.

Which block each position owns, and the screen there now or last, is in
`~/.local/state/kubaos/hypr/workspace-screens`, with the group's name, if it
has one, in a fifth column. The Command menu lists it: type "workspace
group" for an Item per position, "Workspace group 1" ("Workspace group 1:
Left" once named), with its workspaces and its screen; running it goes
there, or opens the group's first workspace when it has none. A file from before
positions, keyed by screen, is turned into positions on the first start: the
externals plugged in keep their blocks where they stand, the screens not
plugged in take the positions before the first one held, in the order they
last sat, and any block left over waits as a group with no position, so no
window or workspace number moves. A file naming a screen at a position and
again waiting at another repairs itself: the waiting row goes once its block
has no windows.

Hyprland reports a screen before it arranges the layout, and a dock's screens
come and go one at a time, so `workspaces.lua` waits for the layout to hold
still (250 ms, restarted by each arrival, removal and layout change) and then
reconciles once, whether the dock brought or took one screen or two; a window
opening or closing never changes which screen owns which block. The output
Hyprland adds while no screen is plugged in (`FALLBACK`) holds no position. The screens
file is written after the workspaces have moved, whole, so the bar never maps
a screen to a block before the block is there.

Each group keeps two workspaces even when they are empty, as Hyprland
persistent workspace rules bound to its screen (`hl.workspace_rule`, set and
released at runtime by `workspaces.lua`): its first, and one after its last
workspace with windows. The bar draws that last one as a faint `+` until it is
shown. Once a window lands on it, the next number is kept in its place and the
one no longer needed is released. A group full up to 10 keeps no empty one
after it.

Next and previous (`SUPER + Tab`, `SUPER + CTRL + →/←`, `SUPER + wheel`, the
bar's wheel) and the three-finger swipe walk the focused screen's workspaces in
that order, the kept empty ones too. The swipe is Hyprland's own, so it follows
the fingers: swipe slowly to peek at the workspace beside. From a group's last
with windows, next opens the empty one after it, and next again goes to the
first of the group on the right; from a group's first, previous goes to the
last of the group on the left. At either end they stay; the swipe never makes a
workspace (`workspace_swipe_create_new` is off, the kept empty workspace takes
its place). `SUPER + CTRL + ALT + →/←` jump to the first workspace of the next
or previous group. `SUPER + 1..0` address the focused group: the screen's own,
or the waiting group whose workspace it shows, so on a waiting group
`SUPER + 2` is that group's 2.

No workspace is renumbered when a screen comes or goes. The Quickshell the
bar runs (v0.3.2) keeps the id a workspace had when it first saw it, so a
renumbered one shows under its old number and a click on it goes nowhere.

Every action is also an expression for the socket:
`hyprctl dispatch 'dot.workspaces.focus(3)'`,
`dot.workspaces.move_window(3)` (`, false` not to follow),
`dot.workspaces.move_window_to_new()`, `dot.workspaces.move_to_monitor("l")`,
`dot.workspaces.next()`, `previous()`, `next_group()`, `previous_group()`
(each takes a connector, the focused screen without one). The bar's clicks go
through `dot.workspaces.go_to(id, "<connector>")`, its wheel through
`dot.workspaces.next("<connector>")` and `previous`, and the menu's desk Items
through `dot.workspaces.go_to_position("1")` (or `"panel"`). The bar runs
`dot.workspaces.reload_groups()` when the groups file changes.

### Workspace groups: pinning a screen

To give a screen its group whatever the layout, the port or the order the
screens come up in, pin it in
`~/.config/kubaos/desktop/workspaces/groups.toml`, by its description (make,
model and serial, as `hyprctl monitors all` prints it). A table a group,
numbered as the positions are; `name` is optional:

```toml
[group.1]
name = "Left"
screens = ["BNQ ZOWIE XL LCD G4L01663SL0", "Dell Inc. DELL U2724D 5D6E7F8"]

[group.2]
name = "Centre"
screens = ["LG Electronics LG ULTRAGEAR+ 510NTCZN7787", "Dell Inc. DELL U2724D 1A2B3C4"]
```

- A pinned screen stands at its group's number, wherever Hyprland places it.
- Two screens of one group plugged in together: the first listed wins. The
  other counts as unpinned.
- Unpinned screens take the numbers left over, left to right, and never one
  a group pins, even while that group's screens are away: its windows wait
  on the primary screen for one of them.
- Two screens that report the same description (a pair without serials)
  can't be pinned apart: a pin naming that description goes to the leftmost
  of them, and the other counts as unpinned. The Command menu offers no Pin
  Item for either.
- The name shows in the Command menu's desk Items and in the bar, at the
  start of the group's tint while it waits on another screen.

The laptop panel can be pinned too. By default it stands at its own place
and shows 1-10, which stays its block whatever it shows:

- **Lid open.** The panel is a screen like the others. Pinned to group N, it
  shows group N while no screen listed before it in N is plugged in, and its
  own 1-10 waits on it (the primary screen) like any group without a screen,
  tinted in the bar, before group N. Once a screen listed before it is
  plugged in, that screen takes group N and the panel is back on 1-10. A
  screen listed after the panel counts as unpinned while the panel is open.
- **Lid closed.** Hyprland turns the panel off (`dot-hypr-lid`), so it
  holds no group: group N goes to the next screen listed in it that is
  plugged in, else waits on the primary screen, the external Hyprland
  numbered first, beside 1-10, which waits there as it always does with the
  lid closed. Opening the lid gives the panel group N back.

So with `screens = ["LG Electronics …", "China Star … MNE007ZA3-2"]` the
panel shows the centre group on the road and the LG shows it at home; with
the panel first, the panel keeps the group at the desk while open, and the
external takes it when the lid closes.

The file applies as it is saved: the bar watches it and, once it has held
still for a moment, runs `dot.workspaces.reload_groups()`, which reads it
again and moves each group to the screen it now pins, the same as a
hotplug, at once or once a layout change in progress settles. The Command
menu's edits run it themselves too, so they apply with the shell down; a
file read twice moves nothing the second time. An editor saving by rename
leaves the file missing for an instant: a read that finds it missing when
it was there reads again after the wait, and only a file still missing then
pins nothing. Hyprland also reads it whenever its config loads.

A file that doesn't read (a key it doesn't know, a screen in two groups,
anything but `[group.N]` tables of `name` and `screens` as one-line
strings) pins nothing until it is fixed: every screen takes its place left
to right. A notification says what is wrong, and where. At login Hyprland
reads the file before the shell, the notification server, is up, so the
notification is tried once a second for a minute until it shows, and only
a problem shown is not shown again after a config reload.

In the Command menu, "Pin <screen> to group N" (for each screen plugged in,
to each group and to a new one), "Unpin <screen>" and "Name group N…" write
the file, keeping its comments; "Open workspace groups settings" opens it.

## Lid

`switch:on/off:Lid Switch` binds call `dot-hypr-lid`. It turns `eDP-1` off
only when another monitor is active, via a flag file in
`$XDG_RUNTIME_DIR/dot-hypr/` that `monitors.lua` reads, then `hyprctl reload`.
If the switch has another name on this machine, check `hyprctl devices` and
fix the two binds at the bottom of `keybinds.lua`. Suspend on lid close is
logind's job (battery only), configured in `system/`, while the idle
settings' `lid` says the same. When it says anything else, `kubaos-idle`
holds the lid away from logind for the session and the close bind's
`kubaos-idle lid closed` does it; docked, it does nothing.

## Editor support

`.luarc.json` points LuaLS at `/usr/share/hypr/stubs`, which the Hyprland
package ships, for completion of the `hl.*` API.

The option and rule names used in `looks.lua` and `rules.lua` were checked
against the Hyprland v0.56.2 source: `src/config/values/ConfigValues.cpp` for
`decoration:blur:*`/`shadow:*`, and the layer rule effects in
`src/config/lua/bindings/LuaBindingsConfigRules.cpp` (`blur`, `ignore_alpha`,
`no_anim`, `animation`). `focus.lua`'s strike relies on the same source:
`window.active` passing the focus reason (`src/config/lua/LuaEventHandler.cpp`,
`eFocusReason` in `src/desktop/state/FocusState.hpp`), a repeating `hl.timer`
being disarmed by `set_enabled(false)`, a colour set at run time going through
the window's border and shadow fades (`CWindow::updateDecorationValues`), and a
fade whose leaf is off jumping straight to its value
(`src/animation/AnimationManager.cpp`). The Lua syntax is checked with
`luac5.5 -p *.lua`.

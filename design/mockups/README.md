# The mockup site

Every UI KubaOS has, as it is meant to be: the single source of truth the builds match. The mockup skill (`.claude/skills/mockup/SKILL.md`) says what a mockup is and what its page must show; this file says how the site works and how a page is added.

## Running it

In `nix develop`, which provides Node, the tokens' generator and Chromium:

| Command | What |
|---|---|
| `just mockups` | Serves the site with hot reload at the address Vite prints. A change to `design/tokens.toml` regenerates `src/tokens.css` and the page follows it. |
| `just mockups-build` | Type-checks and builds it static into `dist/`. |
| `just mockups-check` | Draws every page at every scale, light and dark, and holds its boxes to the geometry rules and each mocked component to its twin on the specimen's pages (`docs/DESIGN.md`, "The mockups"). Part of `just design-check`. |
| `just shots mockups` | Renders the pages' shots, before and after (`docs/agents/design-pr-loop.md`). |

Plain HTML, CSS and TypeScript, built by Vite; no UI framework. The npm dependencies are locked in `package-lock.json`, and `playwright-core` is the version of nixpkgs' Playwright, whose Chromium draws the shots and frames. Use a Chromium-based browser: the icons' stroke uses CSS typed arithmetic.

## The toolbar

Every page has it: light or dark, the scale (1, 1.25, 1.5, 2), reduce motion, the speed, the focus stutter, the text's length (short, long, a translation 40% longer) and a window size for templates and screens. The page's box is zoomed out by the display's own pixel ratio, so inside it a CSS pixel is a device pixel at every scale: hairlines and the grid land as they do in the builds. Mode, scale and motion apply through CSS custom properties at once; the text's length draws the page again. Each setting is kept in the address (`?mode=light&scale=1.5`) and for the next visit.

A CSS pixel is a device pixel only at a whole pixel ratio: Chromium lays a page out in steps that don't divide a fractional one. On a screen at 1.25, the toolbar says so and names the browser zoom that makes the ratio whole (80%). The shots and `just mockups-check` draw at a ratio of 1.

## Where things are

| Path | What |
|---|---|
| `src/tokens.css` | Generated by `kubaos-tokens` (ignored by git): every token as a custom property. A length is its logical pixels times `--px`, recomputed in every `.mock` box. |
| `src/lib/` | The mocked components and their parts (`text`, `icon`, `row`, `button`, the focus ring), each the twin of `kubaos-ui`'s and carrying the specimens' probe. |
| `src/site/page.ts` | The page API: what a page says. |
| `src/site/parts/` | The parts every page is drawn with: the state matrix, the motion player, the keyboard panel, the measures overlay, the description block. |
| `src/pages/LEVEL/PAGE.ts` | One page each; `src/pages/index.ts` lists them. |
| `scripts/render.ts` | Draws the built site in headless Chromium, as shots and geometry frames. |

## Adding a page

1. Write `src/pages/LEVEL/PAGE.ts` with `page({ … })` from `src/site/page.ts`, LEVEL one of `foundations`, `atoms`, `molecules`, `templates`, `shell`, `kobo` or `apps`. `src/pages/atoms/button.ts` is the example.
2. Add it to `PAGES` in `src/pages/index.ts`.
3. Add its line to `test/shots/surfaces`: `mockups/PAGE  design/mockups/src/pages/LEVEL/PAGE.ts`.

Every part is required, and the types refuse a page without one, or with an empty list where one is needed: `live` (the thing itself, beside the description), `description`, `variants`, `sizes`, `states`, `content` (text, a missing picture, none/one/many), `motion` (arriving, leaving, between states, each move with its duration and its curve, an easing or `neon.strike`'s steps), `keyboard`, `measures` (the samples the overlay outlines, every measure by its token, and the reflow across window sizes). A part that doesn't apply is `doesntApply("why")`, and the page shows the reason in its place. The state matrix names the states it shows; each of the others (rest, hovered, pressed, focused, disabled, selected, loading, empty, error) gets its reason in `absent`. Light and dark at every scale come from the toolbar on every page.

A mock is built only from `src/lib`'s parts and the tokens: no number, colour or duration written out. A new mocked component is a module in `src/lib/` that wraps its root in `probe()` with its shared name, variant and fixed measures, as `kubaos-ui`'s `probe::component` does, so `just mockups-check` can hold the builds to it.
